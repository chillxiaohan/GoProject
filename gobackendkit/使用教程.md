# gobackendkit 实操教程（从零跑通）

本教程按「拷贝框架 → 配库 → Excel 建表 → 启动 → 调接口确认」书写。  
示例程序在 `examples/quickstart`，建表工具在 `cmd/excelddl`。

---

## 0. 你需要先准备

| 软件 | 用途 |
|------|------|
| Go 1.22+（本仓常用 1.25） | 编译运行 |
| PostgreSQL（推荐）或 SQL Server | 业务库 |
| Redis | 会话/缓存探测 |
| Excel / WPS | 编辑表结构 `.xlsx` |

本机确认：

```bat
go version
```

---

## 1. 把框架拷贝到哪里

任选一个工作目录，例如：

```text
D:\MyProjects\
  gobackendkit\          ← 整个框架目录拷到这里（含 go.mod、db、auth、cmd、examples…）
  （以后新业务项目可与 gobackendkit 并列）
```

**不要只拷某个子文件夹**；必须保留完整 `gobackendkit`（含 `go.mod` / `go.sum`）。

下面命令均以「先 `cd` 进 `gobackendkit` 根目录」为准。

---

## 2. 复制示例项目并填写数据库 / Redis

```bat
cd D:\MyProjects\gobackendkit\examples\quickstart
copy conf\env.example conf\env
notepad conf\env
```

按你本机改这些项（示例默认连本机 `kit_demo` 库）：

```ini
DB_TYPE=postgresql
DB_HOST=127.0.0.1
DB_PORT=5432
DB_USER=postgres
DB_PASSWORD=你的密码
DB_NAME=kit_demo

REDIS_ADDR=127.0.0.1:6379
REDIS_PASSWORD=
REDIS_DB=0

HTTP_ADDR=:8090
```

**重要：** 表只会建在 `DB_NAME` 指定的库里。用 Navicat 时，左侧必须点开**同一个库**（例如 `kit_demo`）再刷新「表」，看 `postgres` / `erp` 库是看不到的。

若库还不存在，先执行：

```sql
CREATE DATABASE kit_demo;
```

## 3. 用 Excel 设计表结构

### 3.1 生成示例 Excel（推荐先跑通）

在 **gobackendkit 根目录**执行：

```bat
cd D:\MyProjects\gobackendkit
go run ./cmd/excelddl -gen-sample examples/quickstart/schema/demo_items_sample.xlsx
```

成功后终端会打印**绝对路径**，例如：

```text
已生成示例 Excel 文件:
   D:\MyProjects\gobackendkit\examples\quickstart\schema\demo_items_sample.xlsx
说明: demo_items 是该文件里的「工作表名称」（Excel 底部标签），不是单独的文件名。
```

| 容易混淆的点 | 正确理解 |
|--------------|----------|
| 找名叫 `demo_items` 的文件 | **没有**这个文件名；文件叫 `demo_items_sample.xlsx` |
| `demo_items` 在哪 | 用 Excel/WPS **打开**上面的 `.xlsx`，看窗口**左下角工作表标签** |

打开后点第 3 行起单元格右侧的 **▼** 才能弹出可选项（黄色小字是提示，不是下拉）：

- **类型**：INT、NVARCHAR、TIMESTAMP、DECIMAL、JSON 等
- **长度**：32、255、MAX、18.2 等（也可手填；DECIMAL 用 `18.2` 表示精度）
- **非空 / 唯一 / 主键**：是 / 否（留空 = 否）

生成后请重新打开文件；旧版 xlsx 需重新 `-gen-sample` 覆盖。

资源管理器打开目录：

```text
D:\MyProjects\gobackendkit\examples\quickstart\schema\
```

里面应有 `demo_items_sample.xlsx`。双击用 Excel 打开即可看到工作表 `demo_items`。

### 3.2 Excel 填写规则

| 约定 | 说明 |
|------|------|
| **工作表名** | = 数据库**表名**（英文，如 `demo_items`） |
| 第 1～2 行 | 表头说明（工具忽略） |
| **从第 3 行起** | 每个业务字段一行 |
| 列顺序 | 注释 \| 字段名 \| 类型 \| 长度 \| 非空 \| 唯一 \| 主键 \| 默认值 |

类型常用：`NVARCHAR`、`INT`、`TEXT`、`BIT`/`BOOLEAN`、`TIMESTAMP`、`DECIMAL`、`JSON`。

工具会**自动追加**审计列（勿在 Excel 里重复写）：

`id`、`create_time`、`create_user`、`update_time`、`update_user`、`is_delete`

非空/唯一/主键列填：`是` / `1` / `true` 表示是，留空表示否。

可继续用 Excel 加工作表 = 加新表，保存后重新执行第 4 步。

## 4. 执行建表（配置数据库表）

仍在 **gobackendkit 根目录**，用 quickstart 的 `conf/env` 连库：

```bat
cd D:\MyProjects\gobackendkit

REM 先看 DDL（不写库）
go run ./cmd/excelddl -excel examples/quickstart/schema/demo_items_sample.xlsx -env examples/quickstart/conf/env -dry-run

REM 正式建表（表已存在则跳过）
go run ./cmd/excelddl -excel examples/quickstart/schema/demo_items_sample.xlsx -env examples/quickstart/conf/env
```
成功时终端会打印：

```text
将连接: type=postgresql host=127.0.0.1 port=5432 user=postgres dbname=kit_demo
模式: 执行建表（请在客户端刷新同一库查看）
创建成功: demo_items
```

若打印的是 `模式: dry-run`，说明加了 `-dry-run`，**不会真正建表**。  
若打印 `已存在，跳过创建`，说明该库里已经有这张表。

## 6. 调用基础测试接口（确认 Redis / 数据库）

另开一个终端（PowerShell 可用 `curl.exe`）：

```bat
curl.exe http://127.0.0.1:8090/health
curl.exe http://127.0.0.1:8090/ping/db
curl.exe http://127.0.0.1:8090/ping/redis
curl.exe http://127.0.0.1:8090/demo/items
```

| 接口 | 成功大致返回 | 含义 |
|------|----------------|------|
| `/health` | `"ok": true` | 进程活着 |
| `/ping/db` | `"db":"ok","select":1` | **数据库连接 + 查询成功** |
| `/ping/redis` | `"redis":"ok"` | **Redis 读写成功** |
| `/demo/items` | `"ok": true, "data":[]` | 业务表可查（空数组也正常） |

若 `/ping/db` 失败：检查 `conf/env`、库是否已创建、防火墙/端口。  
若 `/ping/redis` 失败：检查 Redis 是否启动、`REDIS_ADDR`。  
若 `/demo/items` 报错缺表：回到第 4 步执行 `excelddl`。

浏览器也可直接打开：

- http://127.0.0.1:8090/health  
- http://127.0.0.1:8090/ping/db  
- http://127.0.0.1:8090/ping/redis

## 7. 之后如何加自己的业务

1. 在 Excel 增加工作表 / 字段 → 再跑 `excelddl`  
2. 在 `examples/quickstart`（或你新建的业务目录）里加 `HandleFunc`  
3. 需要登录时：实现 `gobackendkit/auth.Authenticator`，用 `auth.NewMiddleware` 包一层（见下文「鉴权注入」）

新业务项目推荐目录：

```text
D:\MyProjects\
  gobackendkit\           ← 框架（可只备份这一份）
  myapp\                  ← 你的后台
    go.mod                ← replace gobackendkit => ../gobackendkit
    conf\env
    main.go
    handlers\
```

`myapp/go.mod` 示例：

```go
module myapp

go 1.25.7

require gobackendkit v0.0.0

replace gobackendkit => ../gobackendkit
```

## 8. 鉴权注入（可选，登录后再做）

框架不绑定你们的用户表。登录校验步骤：

1. 实现 `Authenticate(ctx, token) (auth.Principal, error)`（查 Redis 会话 + 用户表）  
2. `gate := auth.NewMiddleware(你的实现)`  
3. `http.HandleFunc("/api/xxx", gate.Handler(你的Handler))`  
4. Handler 内用 `auth.PrincipalFromContext(r.Context())` 取当前用户  

角色 / 功能权限仍由业务自己判断；注入只解决「有没有登录、用户是谁」。

## 9. 只备份框架时拷贝什么

拷贝整个 **`gobackendkit` 目录**即可（含 `cmd`、`examples`、`使用教程.md`）。  
不要指望只拷 `db` 一个包能独立编译。

本仓「项目管家」ERP 在 `erp_services`，通过 `replace` 引用框架，**不属于**框架备份范围。

## 11. 看不到 demo_items 时怎么查

1. **有没有执行过「真正建表」？**  
   `-gen-sample` 只生成 Excel；`-dry-run` 只打印 SQL。必须跑**不带** `-dry-run` 的 `excelddl`，并看到 `创建成功: demo_items`。
2. **客户端连的是不是同一个库？**  
   看建表命令打印的 `dbname=...`，在客户端里切换到该库再刷新（示例默认 `kit_demo`；看 `postgres` / `erp` / `erp_test` 会是空的）。
3. **有没有 `conf/env`？**  
   只有 `env.example` 不够，要 `copy conf\env.example conf\env` 并改密码。  
   命令里的 `-env` 路径要对：`examples/quickstart/conf/env`。
4. **本机验证 SQL：**

```sql
SELECT current_database();
SELECT tablename FROM pg_tables WHERE schemaname = 'public' AND tablename = 'demo_items';
```
