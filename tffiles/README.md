# TFFiles — 轻量级时序数据库 (TSDB)

TFFiles 是一个用 Go 语言编写的高性能、轻量级时序数据库引擎，专为工业物联网（IIoT）和传感器数据场景设计。它提供了高效的数据写入、压缩存储、时间范围查询、分层存储与自动过期清理等完整能力，并通过自定义 TCP 二进制协议对外提供服务。

## 核心特性

- **高性能写入** — 批量写入、异步刷盘、缓冲合并，单次处理数千数据点
- **多字段数据点** — 支持 `float32` 多值字段，适用于设备多传感器场景（如行程、俯仰角、旋转、状态等）
- **混合压缩** — 使用 ZSTD 压缩大块数据，支持 1~9 压缩级别
- **可选差分编码** — 针对时序特点提供增量编码（Delta）和二阶差分编码（Delta-Delta），减少数据体积
- **按天分片存储** — 数据按设备 ID + 日期分目录、分文件，便于管理和清理
- **热/冷分层存储** — 最近 N 天数据存放于热存储（快速访问），历史数据自动迁移至冷存储（高压缩比）
- **时间范围索引** — 每 64KB（可配置）生成一个索引条目，支持二分查找快速定位数据块
- **数据块校验** — 每个数据块写入时附带 CRC32 校验码，读取时自动验证数据完整性
- **自动过期清理** — 超出保留期限的数据文件自动删除，无需人工干预
- **自定义 TCP 二进制协议** — 紧凑、高效的线层协议，减少网络开销
- **并发查询** — 跨多天的查询自动按天并发执行，降低查询延迟
- **活跃连接统计** — 内置服务器统计监控（连接数、写入量、查询量、网络流量）

## 项目结构

```
.
├── main.go                # 入口：启动存储引擎 + TCP 服务器
├── datapoint.go           # DataPoint：固定 16 字节（int64 时间戳 + float64 值）
├── simple_datapoint.go    # SimpleDataPoint：灵活多字段（int64 时间戳 + []float32）
├── encoder.go             # OptimizedEncoder：Delta / Delta-Delta 差分编码器
├── storage.go             # Storage：存储引擎（写入、查询、分层、清理）
├── writer.go              # DayWriter：按天文件写入器（缓冲、压缩、索引、CRC校验）
├── reader.go              # DayReader：按天文件读取器（索引查询 + 全量扫描 + CRC校验）
├── tcp_server.go          # TCPServer：自定义二进制协议 TCP 服务端
├── go.mod / go.sum        # Go 模块定义
└── data/                  # 数据目录（运行后自动创建）
    ├── hot/               # 热数据目录
    └── cold/              # 冷数据目录
```

## 快速开始

### 构建

```bash
go build -o tffiles .
```

### 运行

```bash
./tffiles
```

启动后默认监听 `:8081`，数据存储在 `./data/` 目录下。

### 使用示例

**写入数据（使用 TCP 客户端）：**

```go
// 连接到服务器
conn, _ := net.Dial("tcp", "localhost:8081")

// 构造写入消息
// [ 4字节: 消息体长度 ][ 1字节: 消息类型(0x01=写入) ][ 2字节: 设备ID长度 ][ 设备ID ][ 4字节: 点数 ][ 点数据... ]
// 每个点: [ 8字节: 时间戳(ns) ][ 2字节: 字段数 ][ 字段数 * 4字节: float32值 ]

// 写入 100 个数据点
msg := buildWriteMessage("device_001", points)
conn.Write(msg)
```

**查询数据：**

```go
// 构造查询消息（大端序）
// [ 4字节: 消息体长度 ][ 1字节: 查询类型(0x02) ][ 2字节: 设备ID长度 ][ 设备ID ][ 8字节: 开始时间 ][ 8字节: 结束时间 ]
conn.Write(queryMsg)

// 读取响应
// [ 4字节: 消息体长度 ][ 1字节: 查询类型 ][ 1字节: 状态码 ][ 4字节: 点数 ][ 点数据... ]
```

### 配置调整

编辑 `main.go` 中的配置：

```go
config := DefaultConfig("./data")
config.HotDays       = 3        // 热数据保留天数
config.RetentionDays = 30       // 总保留天数
config.CompressLevel = 6        // ZSTD 压缩级别 1-9
config.IndexInterval = 64 * 1024 // 索引间隔（字节）
config.MaxMemoryMB   = 512      // 最大内存（MB）
```

## 数据模型

### DataPoint（定长、高效）

```go
type DataPoint struct {
    Time  int64   // 纳秒级时间戳
    Value float64 // 浮点数值
}
```
编码后固定 **16 字节**（8 字节时间戳 + 8 字节值），适用于单值监控场景。

### SimpleDataPoint（灵活、多字段）

```go
type SimpleDataPoint struct {
    Timestamp int64     // 纳秒级时间戳
    Values    []float32 // 动态数量 float32 字段（4 字节/个）
}
```
编码格式：`[时间戳:8字节] [字段数量:2字节] [值1:4字节] [值2:4字节] ...`

适用于设备多传感器场景，例如预定义的 6 字段设备数据：
- `field_0`：行程（Travel）
- `field_1`：俯仰角（Pitch）
- `field_2`：旋转（Rotation）
- `field_3`：料位状态（StockStatus）
- `field_4`：取料状态（ReclaimStatus）
- `field_5`：PLC 状态

## 存储机制

### 按天分文件

数据按 **设备 ID** 和 **日期** 组织目录结构：

```
data/
├── hot/
│   ├── device_001/
│   │   ├── 2026-06-01.tsdb       # 数据文件
│   │   ├── 2026-06-01.tsdb.idx   # 索引文件
│   │   ├── 2026-06-02.tsdb
│   │   └── 2026-06-02.tsdb.idx
│   └── device_002/
│       └── ...
└── cold/
    └── device_001/
        └── 2026-05-30.tsdb       # 已迁移的冷数据
```

### 分层存储（Hot / Cold）

- **热数据（Hot）**：最近 `HotDays` 天的数据，存储在 `data/hot/` 目录下
- **冷数据（Cold）**：超出 `HotDays` 的数据自动迁移至 `data/cold/` 目录
- 迁移过程采用**原子写入策略**：先写入 `.tmp` 临时文件，再执行 `os.Rename` 重命名为最终文件，确保断电或崩溃时不会产生不完整数据文件
- 迁移时自动以 **最高压缩比（级别 9）** 重新压缩冷数据，节省磁盘空间
- 数据分层守护协程每 **6 小时** 执行一次

### 索引加速

每个数据文件附带同名 `.idx` 索引文件，每个索引条目 36 字节（含 CRC32 校验码）：

```go
type IndexEntry struct {
    StartTime int64  // 起始时间
    EndTime   int64  // 结束时间
    Offset    int64  // 文件内偏移
    Length    int64  // 压缩块长度（含4字节CRC32）
    CRC32     uint32 // 数据块CRC32校验码
}
```

- 默认每 **64KB** 写入后生成一个索引条目
- 索引文件为追加写入，与数据文件保持同步
- 查询时通过 **二分查找** 快速定位目标数据块，读取后自动验证 CRC32

### 数据清理与过期

- 每天自动扫描超出 `RetentionDays` 的数据文件并删除
- 数据文件和对应的索引文件一并清理
- 通过 goroutine 定时执行（每 24 小时）

## 传输协议

采用自定义 TCP 二进制协议，消息格式如下：

### 消息格式

```
[ 消息体长度: 4字节 (uint32, BigEndian) ]
[ 消息类型:    1字节 ]
[ 消息体:      N字节 ]
```

**消息类型定义：**

| 类型 | 值 | 方向 | 说明 |
|------|-----|------|------|
| 写入 | 0x01 | 客户端 → 服务端 | 批量写入数据点 |
| 查询 | 0x02 | 客户端 → 服务端 | 时间范围查询 |
| —— | —— | —— | —— |
| 成功 | 0x00 | 服务端 → 客户端 | 响应状态码 |
| 错误 | 0x01 | 服务端 → 客户端 | 响应状态码 |

### 写入请求

**消息体格式：**

```
[ 2字节: 设备ID长度 (uint16) ]
[ 设备ID: 变长 ]
[ 4字节: 数据点数量 (uint32) ]
[ 数据点 1:
  [ 8字节: 时间戳 (int64, 纳秒) ]
  [ 2字节: 字段数 (uint16) ]
  [ 字段 1: 4字节 (float32) ]
  [ 字段 2: 4字节 (float32) ]
  ...
]
[ 数据点 2: ... ]
[ ... ]
```

**成功响应：** 6 字节 `[消息体长度=1][消息类型=0x01][状态码=0x00]`
**错误响应：** `[消息体长度=1+len(错误消息)][消息类型=原始请求类型][状态码=0x01][错误消息]`

### 查询请求

**消息体格式：**

```
[ 2字节: 设备ID长度 (uint16) ]
[ 设备ID: 变长 ]
[ 8字节: 起始时间 (int64, 纳秒) ]
[ 8字节: 结束时间 (int64, 纳秒) ]
```

**查询响应体格式：**

```
[ 4字节: 数据点数量 (uint32) ]
[ 数据点 1:
  [ 8字节: 时间戳 (int64, 纳秒) ]
  [ 2字节: 字段数 (uint16) ]
  [ 字段 1: 4字节 (float32) ]
  [ 字段 2: 4字节 (float32) ]
  ...
]
[ 数据点 2: ... ]
[ ... ]
```

## 性能优化

### 数据压缩

采用 **ZSTD** 压缩算法，按块压缩：

| 配置级别 | ZSTD 模式 | 适用场景 |
|----------|-----------|----------|
| 1 | `SpeedFastest` | 追求写入速度，容忍更大存储 |
| 2~3 | `SpeedDefault` | 平衡速度与压缩比 |
| 4~6 (默认) | `SpeedBetterCompression` | 推荐日常使用 |
| 7~9 | `SpeedBestCompression` | 归档/冷数据，极致压缩比 |

- 小于 `IndexInterval`（默认 64KB）的块**不压缩**，避免小块压缩效率低
- 冷数据迁移时自动使用级别 9 重新压缩

### 缓冲批量写入

- 写入缓冲池上限 **1000 条**，达到阈值触发刷盘
- 定时器每 **1 秒** 自动刷盘一次，防止数据长时间驻留内存
- 每次刷盘后执行 `file.Sync`，确保数据持久化到磁盘
- 使用 `sync.Pool` 复用缓冲区，减少 GC 压力

### 编码策略

`OptimizedEncoder` 提供了三种编码模式（适用于 `DataPoint` 单值场景）：

| 模式 | 每点大小 | 最佳应用 |
|------|----------|----------|
| 原始编码（Raw） | 16 字节 | 通用场景 |
| 增量编码（Delta） | ~8-12 字节 | 采样间隔相对稳定的数据 |
| 二阶差分（Delta-Delta） | ~4-8 字节 | 变化规律平缓的数据 |

## 配置项

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `DataDir` | `./data` | 数据存储根目录 |
| `HotDays` | `3` | 热数据保留天数，之后迁移到冷存储 |
| `RetentionDays` | `30` | 数据总保留天数，过期自动清理 |
| `CompressLevel` | `6` | ZSTD 压缩级别（1-9） |
| `IndexInterval` | 64KB | 生成索引条目的字节间隔 |
| `MaxMemoryMB` | 512 | 最大允许使用的内存（MB） |
